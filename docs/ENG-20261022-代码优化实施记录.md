## 二、逐项改动

### 1. 修复 ContentHash 载荷的条件嵌套缺陷（**真 bug**）

`RecipeStore.ComputeHashStatic` 里 `growBoxScale / growBoxElong / growBoxPad / growDiagonal / growIters / openSeverDilate / openBiteFrac / typeTree / featureConfidence / footprintTau / footprintMargin / seedZ / seedZAbs / zEps / zWindow / zCopperRadius / subpixelGradient` 全部缩进在 `if (r.TypeRefineTopology)` 块内。

后果：`typeRefineTopology=false` 的配方改上面任何一个参数，**hash 不变 → 换型确认门闩静默失效**，用旧确认跑新参数。现行 v1.2.1 恰好 `typeRefineTopology=true`，所以问题从未暴露。

改法：把这些字段移出该块（位置不变，顺序不变）。v1.2.1 的 payload 逐位相同 → 冻结 hash 不变；`typeRefine=false` 的配方则从「漏」变为「有」。

### 2. 新增 hash 契约测试（把「靠人记」变成「靠测试拦」）

`src/DeepPCBStation.Core.Tests/RecipeHashContractTests.cs`：
- `EveryWritableProperty_AffectsHash`：反射遍历 `RecipeConfig` 全部可写属性，逐个改值并要求 hash 必须变化；漏掉的字段在断言消息里被点名。→ 以后新增参数忘记并入 payload，测试直接红。
- `GrowParams_AffectHash_EvenWithoutTypeRefine`：专防第 1 条的回归。
- `ShippedRecipe_KeepsFrozenHash`：冻结 hash 锚点 + 断言现行配方零诊断。

### 3. 配方加载：从「静默跳过」到「可诊断 + 响亮失败」

- 删除 `catch { /* skip */ }`；解析失败进 `RecipeStore.Diagnostics`（带文件名与异常类型）。
- 目录内 JSON **全部**失败时抛 `InvalidDataException`（含逐文件原因），不再退回默认配方继续跑。
- 新增 `RecipeStore.Validate`：量纲/区间/互斥校验（`diffThreshold 1~255`、`maxBlobArea < minBlobArea`、各类比例 ∈ (0,1]、`openRadiusNeg ≥ -1`、`footprintTau × growBoxScale` 互斥 WARN…），加载即校验。
- 诊断上屏：`StationServices` 并入 `EngineWarn`（运行页黄条 + 启动日志）；`ConsoleDemo` 打到 stderr。

### 4. 按类型面积闸 `TypeAwareAreaGate`（默认关，机制修复≠调参）

原实现 `selectMin = min(minOpen, minMb)` 同时用于全局预筛与分型后闸门，两类下限中较小的永远顶掉另一个，`MinBlobAreaOpen` / `MinBlobAreaMousebite` 事实上失效。

改法：
- 预筛仍用 `selectMin`（保证候选不被提前杀掉）；
- 分型完成后，若开关打开，按类复核：`MOUSEBITE → minMb`，`OPEN/PINHOLE → minOpen`；
- 开关关闭 → `typeMin = selectMin`，与原实现**逐位相同**。

#### 实测（train1000 拟合集，`MinBlobAreaMousebite=11` + 开关开）

| 指标 | v1.2.1 基线 | 开关+mb11 | Δ |
|---|---|---|---|
| Pred | 6762 | 6794 | +32 |
| TP（忽略分型） | 6646 | 6656 | **+10** |
| TP（严格分型） | 6472 | 6481 | +9 |
| Precision（忽略） | 98.3% | 98.0% | −0.3pp |
| Recall（忽略） | 96.7% | 96.8% | +0.1pp |
| F（忽略） | 97.5% | 97.4% | −0.1pp |
| mAP11（忽略） | 90.6% | 90.6% | 0 |
| F（严格） | 94.9% | 94.8% | −0.1pp |

**结论：机制有效（确实多命中 10 个 GT），但代价是多 32 个候选，净收益为负。**
与 `workpoint_sweep_report.md` 的「降下限买到的是噪声框」一致 —— 说明 `area<min` 那批漏检之所以漏，不是被面积闸误杀那么简单，而是降闸后同位置产生的连通域本身就是噪声主导。

因此**不开启该开关、不改默认值**，符合「一轮不过永久停」纪律。机制保留，供后续与分区阈值 / σ 场联用时复用（那时噪声底变了，这个开关才有意义）。
`minMb=16` 的第二档因耗时中止（单档约 8 分钟），结论方向已由 11 档给出，不再补。

## 三、未做（及原因）

| 项 | 原因 |
|---|---|
| H2 多金板 σ 容差场 | 需产线采 5~10 块良品 + 配方资源字段 + σ_floor 拟合 + 四集验收；是算法主线变更，须单独开票过反驳审查。且会引入逐像素 μ/σ，必须同步做积分图 O(1)，否则单检 413ms 会显著上升。 |

## 四、下一步建议（按顺序）

1. 把 `tools/verify.ps1` 接进 CI（self-hosted Halcon runner），让「零退化」从人肉变自动。
2. 做 M1 拆分时先补阶段单测（差分/形态学/剪枝合成图各一组），再逐阶段搬迁，每步跑 `verify.ps1`。
3. H2 σ 场立项：先做「离线仿真 + 积分图原型」，在 train1000 上量 z 通道对鬼影的压制率，再决定是否动检测主线。
4. 若要继续啃 `area<min`：本批已证明「单纯降面积下限」买入的是噪声，方向应转向**形态**（残渣长回足迹已在 v1.2.2 证伪）或**分区阈值**（铜厚/油墨差异导致的阈值该分区而非全局）。

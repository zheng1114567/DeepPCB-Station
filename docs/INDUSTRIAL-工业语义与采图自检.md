# 工业视觉能力补齐：四态判定 + 采图有效性自检 + 工业 KPI

日期：2026-10-22　状态：**已落地并自验收**（默认关闭，生产行为零变化；开启需先标定）

关联：`docs/AOI工业化算法升级方案.md`（P2 三态输出 / 采集有效性自检 / FCR+Escape 指标）
纪律依据：`docs/QUALITY_DEBT.md`（拟合集增益必须过留出集；未量测不得上闸）

---

## 一、为什么做这个（而非继续拧阈值）

`docs/QUALITY_DEBT.md` 已实证：检出 / 排序 / 分型三杠杆在「模板差分 + 形态学 + 规则分型」范式内**全部封顶**
（官方 test 500 对：严格分型 F 94.4% / mAP11 88.2%，检出口径 F 97.0% / mAP11 90.2%）。
继续调阈值换不来准确率，但**「工业视觉能力」缺的不是准确率，是产线语义**：

| 缺口 | 后果 | 本轮补齐 |
|---|---|---|
| 只有 OK/NG 二态 | 采图没拍好的板被当成 NG → **过杀里混着采图问题，FCR 永远降不下来** | 四态：OK / NG / **REVIEW** / **INVALID** |
| 无采图有效性自检 | 失焦/过曝/空图/上错料号照样出检测结论，结论不可信却计入良率 | `CaptureQuality` 自检（前置，检测前拦截） |
| 指标只有 F1 / mAP | 框级指标掩盖「假点堆在少数板上」，与复判人力、客户投诉口径对不上 | 评测器补 **FCR（每板假点数）** 与 **Escape Rate（板级漏放率）** |
| 疑似缺陷直接判 NG | 复判工位被低置信疑似淹没 | `ReviewPolicy`：低置信整板转 REVIEW |

**本轮不碰任何检出闸门、不改任何阈值**，因此与「三杠杆封顶」无冲突——换的是**口径与鲁棒性**，不是精度。

## 二、四态判定

`InspectionResult.VerdictKind`：

| 态 | 触发 | 处置 | 计入良率 |
|---|---|---|---|
| `Ok` | 无缺陷 | 放行 | 是 |
| `Ng` | 有缺陷且置信度够 | 判废/返修 | 是（分母） |
| `Review` | 有缺陷但最低置信度 < 复判线（默认 0.35） | **人工复判** | 是（保守按不合格计） |
| `Invalid` | 采图自检未通过 | **重拍** | **否**（不计过杀） |
| `Fault` | 引擎/无图/未确认换型 | 报修 | 否 |

判定文本：`OK` / `NG` / `REVIEW` / `INVALID:CODE` / `FAULT:CODE` / `VOID`。

**握手语义修复（重要）**：采集无效的板原先会经 `result.IsOk==false` 被回成 **NG**
——等于把一块没看清的好板判废。现置 `FaultCode=CAPTURE_INVALID:<CODE>`，
握手走既有 FAULT 分支回上位机（请求处置），**不回 NG**，协议字段不变。

已知边界（如实记录）：REVIEW 板在现有握手协议里仍回 NG（协议无 REVIEW 码位）。
这是**保守方向**（不会漏放），但会略微抬高复判量；改协议需与上位机约定，列为待办。

## 三、采图有效性自检（`Core/Imaging/CaptureQuality.cs`）

纯函数、不依赖 Halcon、检测前调用。判据一律用 **test 相对 template 的相对量**
（换型/换批次不需重新标定，避免绝对阈值随料号失效）。

| 原因码 | 判据 | 默认阈值 |
|---|---|---|
| `FLAT` | 灰度标准差过小（未出图/遮光/白图） | std < 3.0 |
| `OVER_EXPOSURE` | 对比度比塌陷 且 均值偏亮 | contrastRatio < 0.7 且 meanShift > +10 |
| `UNDER_EXPOSURE` | 对比度比塌陷 且 均值偏暗 | contrastRatio < 0.7 且 meanShift < −10 |
| `BLUR` | 锐度比 = test/temp 拉普拉斯能量比过低 | ratio < 0.6 |
| `REGISTER_FAIL` | 降采样配准后残余异号像素比例过高（上错料号/严重偏移） | residual > 0.20 |

### 标定（official_test 500 对实测，`--capture-diag`）

| 指标 | min | p05 | p50 | p95 | max |
|------|-----|-----|-----|-----|-----|
| 锐度比 | 1.024 | 1.090 | 1.152 | 1.368 | 2.033 |
| 高饱和 satHi | 16.70% | 28.05% | 67.00% | 91.16% | 98.65% |
| 近黑 satLo | 0.99% | 7.44% | 28.98% | 69.16% | 81.75% |
| 灰度标准差 | 27.0 | 69.4 | 115.7 | 126.6 | 127.2 |
| **对比度比** | 0.944 | 0.971 | 0.997 | 1.005 | 1.119 |
| 均值偏移 | −15.5 | −5.0 | −0.1 | 4.2 | +12.5 |
| 配准残差 | 0.000 | 0.004 | 0.015 | 0.057 | 0.134 |
| 自检耗时 ms | 12.4 | 13.7 | 18.0 | 31.1 | 45.4 |

**零误触发**：当前阈值在 500 块正常板上一个都不触发。

### 标定时发现并修掉的两个真实设计缺陷

1. **绝对饱和闸在本模态下根本不成立。** PCB 图是「暗铜 + 亮基材」的双峰分布，
   正常板 satHi 中位 **67%**、最大 **98.65%**——原先设的绝对上限 0.25 远在正常范围内，
   它没误杀只是因为「相对模板增量」这一项救了场，属潜伏的错配。已改为默认关闭（1.01 不可达）。
2. **过曝的正确可观测效应是对比度塌陷，不是饱和占比上升。** 正向对照里
   「+120 灰度」的合成过曝**抓不到**（基材本就 255，抬亮后饱和占比反而没涨）。
   改用「对比度比 + 均值偏移方向」后即可正确区分过曝/欠曝。
3. 判定顺序调整：曝光/失焦**先于**配准残差判定。严重过曝会让二值图整体翻转而「对不上」，
   但根因是光照（可调），比「上错料号（需换料）」更具体、更可行动。

### 正向对照（闸门必须抓得到真异常）

只证明「不误杀」不够——恒不触发的闸门同样不误杀。合成四类异常验证：

| 合成异常 | 期望 | 实测 | 结论 |
|---|---|---|---|
| 失焦（5×5 均值模糊） | BLUR | BLUR | ✅ |
| 过曝（向 255 压缩至 25% 层次） | OVER_EXPOSURE | OVER_EXPOSURE | ✅ |
| 欠曝（压缩至 35%） | UNDER_EXPOSURE | UNDER_EXPOSURE | ✅ |
| 黑图（全 0） | FLAT | FLAT | ✅ |
| 上错料号（另一块板的图） | REGISTER_FAIL | REGISTER_FAIL | ✅ |

## 四、工业 KPI（评测器 `PcbIcdarEvaluator`）

新增 `Report.Industrial`，与框级 F1/mAP **并列**展示。口径回到**板级**：
复判人力按板计、漏放事故按板计，框级指标会掩盖「假点堆在少数板上」。

官方 test 500 对实测（v1.2.1）：

| 指标 | 值 |
|---|---|
| 板数 | 500 |
| **FCR 每板假点数** | **0.17** |
| 每板假点 P95 | 1 |
| 单板最多假点 | 13 |
| 板级假点率 | 12.4% |
| **板级漏放率 Escape Rate** | **0.00%**（0 / 500） |
| 缺陷级漏放率 | 3.41%（= 1 − 召回） |

**值得写进对外材料的结论**：板级漏放率 **0.00%**——500 块含缺陷板没有一块是「一个缺陷都没抓到」的。
客户投诉的正是「整块板漏放」，这条比框级召回 96.6% 更能说明可用性。
（须同时注明缺陷级漏放率 3.41%，不得只报好看的那个。）

## 五、架构层：`PcbRecipeParams`

`HalconPcbDefectDetector.DetectCore` 开头原先散落 **79 个** `var x = _recipe.Y > 0 ? Y : 默认`
兜底表达式，既无法单测、也无法被新阶段复用，且调用方（如 `Program.cs` 的 `?? "area"`）默认值会与此处打架。
现已全部收敛到 `Core/Detection/PcbRecipeParams.cs`（构造函数按原求值顺序解析，字段沿用原名），
检测器内保留同名别名，下游引用一行未改。

**逐位等价证据**（`--sota-eval --samples=data/official_test` 前后各一次）：

- `sota_eval.json` 扁平化后 **223 个数值字段，0 处不一致**；
- 逐框 dump `miss_dump.tsv`(50) / `fp_dump.tsv`(81) / `iou_near_dump.tsv`(51) **逐字节相同**。

## 六、开关与安全边界

- 采图自检与复判策略在 `appsettings.json` 中**默认关闭**（`CaptureQuality.Enabled=false`、
  `ReviewPolicy.Enabled=false`），未开启时生产路径与改动前**逐位等价**。
- 关闭自检时 `CheckCapture` 直接返回 null，零开销。
- 自检耗时中位 **18ms**（p95 31ms，640×640），相对单检 ~400ms 可接受。

## 七、遗留

1. 握手协议无 REVIEW 码位，复判态目前仍回 NG（保守，不漏放），需与上位机约定后扩展。
2. 采图自检阈值在 DeepPCB（合成 8 位 JPEG、单光源）上标定；**真实产线必须重跑 `--capture-diag` 重新标定**
   ——相对判据能适应批次色差，但阈值裕度需按真实采集链路复核。
3. `docs/AOI工业化算法升级方案.md` 的 S3（多金板 σ 容差场）与 S5（分区阈值）仍未做，
   需产线采良品与 ROI 分区表，非算法侧可独立完成。

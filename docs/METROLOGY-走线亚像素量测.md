# 走线亚像素量测（P1-1 落地记录）

日期：2026-10-22　模块：`Core/Metrology/LineMetrology.cs` + `TraceMeasurementRunner.cs`
定位：**检测 + 量测一体的 AOI 工位**——缺陷检测回答「有没有问题」，线宽/节距量测回答
「工艺参数是否在公差内」。这是 Halcon 量测工具箱（亚像素边缘 + 几何拟合）在 PCB 场景的落地。

---

## 1. 设计纪律（与 CaptureQuality 同模式）

1. **纯函数、不接入检测主线**：调用方显式调用；不加进 `HalconPcbDefectDetector` 的差分流水，
   因此对检出/分型/排序**零影响**（本轮已用 500 对 + 四集金标逐位验证）。
2. **不依赖模板差分**：只用单图灰度，判据全部可解释（边缘位置 → 线宽 → 节距）。
3. **可单测**：合成已知真值的走线图即可验证亚像素恢复精度，精度断言即「合格线」。
4. **ROI 由调用方给定**：量测器**不自动找线**。产线上 ROI 来自示教/配方；
   宁可不测，不可瞎测（半条走线的 ROI 会返回 `TOO_FEW_ROWS` 而不是给一个错数）。

## 2. 算法链路

```
灰度图 + ROI
  → Halcon edges_sub_pix(img, "lanser2", smooth=1, low=20, high=40)   # Lanser2 高斯核亚像素边缘
  → 逐轮廓 GetContourXld 取点，ROI 内过滤（边界用 Math.Round！）
  → 全局 1D 聚类：簇内散布 <0.1px 合成一个边缘位置（MinEdgeGapPx=2px 分裂）
  → 宽度种子 = 有效相邻间距的中位数
  → 贪心配对：间距 ∈ [0.6,1.6]×种子 的两条相邻边缘 = 同一条走线两侧
  → widths/centers → 中位数 + MAD；节距 = 相邻中心距中位数
```

### 两个已踩坑（注释已写进代码，勿再犯）

**坑 1 · 浮点边界**：Halcon 亚像素坐标的「整数值」常是 `299.9999…`。
`(int)` 截断得 `299`，会被 ROI 左/上边界误滤——曾导致每行只剩一个边缘点、全线宽测成 0。
**必须 `(int)Math.Round(px)`。**

**坑 2 · 按行统计只对单走线成立**：原设计「每行最左/最右边缘距离 = 该行线宽」，
ROI 内含 3 条走线时它变成 **ROI 总宽 230px**，配对条件全面失效，节距测成 0。
故改为**全局聚类 + 贪心配对**，与 ROI 内走线条数无关。

**为什么宽度种子用中位数不用最小值**：噪声/伪边缘会造出极小的假间距，
用它当种子会把配对窗口 `[0.6,1.6]×种子` 拉偏，真实边缘反而配不上。
等宽走线的真实间距在直方图里是主峰，中位数对少数离群值免疫（<50% 污染才失效）。

## 3. 精度（合成已知真值走线图）

| 真值线宽 | 实测 | 误差 | 真值节距 | 实测 | 误差 |
|---|---|---|---|---|---|
| 6 px | 5.9922 | 0.008 px | 100 px | 100.0000 | 0.0000 px |
| 12 px | 12.0039 | 0.004 px | 60 px | 60.0000 | 0.0000 px |
| 40 px | 40.0039 | 0.004 px | | | |
| 80 px | 80.0039 | 0.004 px | **标定** | 15μm / 30.0039px → **0.499935 μm/px**（真值 0.5） | |
| 160 px | 160.0039 | 0.004 px | **节距换算** | 100px → **49.993 μm**（真值 50 μm） | |

行间 MAD = 0.0000（合成图无噪声），单次 6–15 ms，位置无关性 <0.3 px。
**⚠️ 这是合成图上的算法精度，不是产线指标。** 真实板的可达到精度取决于
光学分辨率、噪声、边缘对比度，必须用标准件实测后才能对外报。

## 4. 像素当量标定（产线 AOI 的标准做法）

用**一根已知真实宽度的走线当标定尺**：`pixelUm = 真实宽度(μm) / 实测宽度(px)`。
CLI 里就是 `--calib-um=15`。反推只依赖宽度，随后节距等其它量按同一当量换算。
多标定点拟合 + 畸变校正（`vector_to_hom_mat2d`）尚未做——DeepPCB 源图无标定板，
做了也无法在本数据上验证，列为 P2 低优先级。

**批量标定用稳健中位数，不用「第一张」（2026-10-23 修正）**：批量模式下参与标定的
是所有成功样本，取**线宽中位数**（先按 MAD 剔除离群再取中位数）反推当量，
并报告 `CalibSamples` / `CalibOutliers`。原实现取第一张成功样本，那一张一旦测歪，
整批 μm 值会跟着全错且毫无征兆。样本 <4 或离散度为 0 时不剔除（MAD 此时无意义）。

**名义值来源必须写明（否则 PASS 会被误读）**：报告与 JSON 都带 `NominalSource`，
取值为 `CALIB`（名义值=标定尺真实宽度，PASS 表示符合设计值）或
`BATCH_MEAN_UM` / `BATCH_MEAN_PX`（未标定，名义值=本批均值，PASS **仅**表示与同批一致，
**不是**设计公差）。未标定时「线宽公差 PASS 100%」不能对外表述为「符合图纸公差」。

## 5. CLI

```powershell
# 标定模式：给真实线宽，反推当量，节距换算成 μm，按节距公差判定
dotnet run --project src/DeepPCBStation.ConsoleDemo -c Release -- --measure `
  --image=<图或目录> --roi=x0,y0,x1,y1 --calib-um=15 --p-tol=3

# 直接量测：已知当量，线宽/节距都判公差
... --measure --image=<图> --roi=... --um=0.5 --w-tol=0.5 --p-tol=2
```

| 参数 | 含义 |
|---|---|
| `--image=` | 灰度图路径或目录（目录时跑批量 + 重复性统计） |
| `--roi=` | `x0,y0,x1,y1`，须横跨整条走线 |
| `--um=` | 已知像素当量 μm/px |
| `--calib-um=` | 标定模式：该走线真实宽度 μm，反推当量 |
| `--w-tol=` / `--p-tol=` | 线宽/节距公差（±μm；无当量时按 px） |
| `--m-filter/--m-low/--m-high=` | 亚像素边缘滤波器与滞回阈值 |

退出码：0 全部成功；1 参数/路径错误；2 有一张量测失败。
结果落 `reports/trace_measure_<时间戳>.json`。

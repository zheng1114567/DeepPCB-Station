# DL 判别 + 框重建路线：证伪报告（2026-10-22）

## 一句话结论

**「用 DL 区分被闸门误杀的真碎片与鬼影，再重建框救回漏检」这条路线，在official test 上是净亏，应停止投入。**

不是「调参没调好」，是**三重独立的否决**，每一条单独都足以终止路线。

---

## 否决一：几何上限——碎片重建不足以匹配 GT

工具：`tools/rescue_geometry_upperbound.py`
数据：`data/candidates_official_test` + `data/official_test`（500 对）

```
GT 总数 3140   当前漏检 104
漏检 GT 中，附近(6px 内)有被拒候选的:  64（占漏检 61.5%）

重建策略能救回的漏检 GT 比例（IoU≥0.33）
  碎片直接用（现状）        1/64  =  1.6%
  并集外接框                6/64  =  9.4%
  并集框+外扩 6px          29/64  = 45.3%

并集框面积/GT 面积  中位 0.29  p25 0.04  p75 1.51
每个漏检 GT 附近碎片数: {1:31, 2:17, 3:12, 4:2, 5:2}
```

**关键**：即便给免费的外扩预算（现实中的区域生长不可能白拿 6px），上限也只有 45.3%，
而这 29 个 GT 里有一半要靠 m=6~8 的大幅外扩才够——而外扩同时会把正常铜箔圈进框里，
`并集框/GT 面积` 中位仅 0.29 说明碎片普遍远小于 GT，IoU 被系统性稀释。

碎片数分布 `{1:31, ...}` 说明**多数漏检 GT 只有 1 块碎片**，没有可生长的邻域素材。

## 否决二：净收益全网格为负

工具：`tools/rescue_combo_sim.py`（端到端仿真：已上报框不动，被拒候选按模型分重建后加入）

```
基线: TP 3033  FP 83  漏检GT 107  板级漏放 0/500 = 0.00%  FCR 0.166/板
（与评测器 Report.Industrial 的 0.17/板、0/500 完全一致 → 本仿真口径正确）
```

新增 TP / 新增 FP 网格：

| thr \ m | 0 | 2 | 4 | 6 | 8 |
|---|---|---|---|---|---|
| 0.50 | 2/803 | 8/786 | 10/783 | 25/765 | 29/757 |
| 0.70 | 2/625 | 8/609 | 10/603 | 25/582 | 28/574 |
| 0.80 | 1/493 | 6/480 | 8/470 | 21/452 | 25/445 |
| 0.90 | 1/250 | 5/244 | 8/237 | 22/219 | 25/214 |
| 0.95 | 0/135 | 2/131 | 4/129 | 19/112 | 22/109 |

**全网格净收益为负**，最优格（thr=0.95, m=8）也仅 +22TP / +109FP，净 **−87**。
按项目 KPI（FCR 每板假点数 + 板级漏放率必须一起看）这是明确净亏：
现基线 FCR 0.166/板，加这一套直接翻 3 倍以上。

## 否决三：判别力存在，但精确率远达不到工业可用

工具：`tools/official_infer_eval.py`、`tools/eval_gate_stratified.py`、`tools/crossset_calibration.py`

official test 上 AUROC 确实高：

```
整体 AUROC 0.8817   （闸门基线 trivial 0.6584）
闸门内：area<min 0.909 / lop 0.959 / edge 0.836
```

但 **AUROC 高 ≠ 可用**。工业要的是高精确率下的召回。
要查清「到底差多少、是判别力问题还是泛化问题」，做了两项对照。

### 附带验证：判别力是真的，但泛化到 official 就崩了

工具：`tools/gate_group_cv.py`（按板 GroupKFold，同一块板不跨折）

```
参与分折 pair 973（含 867 个纯负板）
分组 OOF AUROC = 0.9451   95%CI [0.9247, 0.9634]   （闸门基线 0.6905）
闸门内：area<min 0.957 / lop 0.972 / edge 0.891
```

**所以判别力是真实的，不是同图泄漏，也不是「只学会了识别闸门」。**
这一点必须如实承认 —— 但它救不了这条路线，因为：

| thr | OOF(train1000) 精确率 | 官方集精确率 |
|---|---|---|
| 0.50 | 40.4% | — |
| 0.80 | 60.6% | — |
| 0.90 | **74.4%** | **14.8%** |
| 0.95 | 100%（仅 9 个） | — |

**同一个 thr=0.90，train 分组 OOF 74.4% → official 14.8%，崩掉 5 倍。**
AUROC 衡量的是排序能力，而工业 KPI 吃的是高精确率下的召回；
分数在分布外泛化时整体下移，直接把工作点从「可用」推到「不可用」。

这解释了否决二里FP 恒定压倒 TP 的根源：**不是重建策略不好，是模型分数在
official 上整体不可信。**

#### 过程中踩到并修掉的一个 bug（值得记住）

`gate_group_cv.py` 首版把折分配只覆盖「含正样本的 973 块板」，
其余 867 个纯负板 `fold_of` 取默认 −1 → **永远只进训练折、从不出现在验证折**。
结果 OOF 验证集只剩 1,965 个候选（vs 全量 18,189），
输出**精确率 100%、AUROC 0.9076**。

修正为「所有 pair 都参与分折」后：验证集 18,189，精确率落到 74.4%，结论全部改写。

**这是 `docs/QUALITY_DEBT.md`「判别性判据必须在全量候选上验」的第三次复现。**
教训具体化：**任何 CV 的分组键必须覆盖全体样本；若只对「含正样本的子集」分折，
默认填充值会把纯负样本系统性地赶出验证集，制造出虚高的精确率。**

## 三条否决的正交性

| 否决 | 说的是什么 | 能否靠调参绕过 |
|---|---|---|
| 几何上限 | 碎片素材本身不足以重建出可匹配框 | 否，素材就那么多 |
| 净收益 | 即便精确率达标，FP 代价压倒 TP 收益 | 否，是 KPI 定义的必然 |
| 泛化落差 | 判别力真实但train→official 精确率崩 5 倍 | 否，是分布外泛化问题 |

三条分别落在「素材」「账」「模型泛化」三个层面，任何一条单独成立即足以终止。

**注意本报告与「判别性不足」主结论的关系**：本轮证伪的是
「把灰度统计重排成权重就能分开」。**判别力本身存在（OOF AUROC 0.945）**，
只是它依赖的特征在跨板泛化时站不住。这比原来「无判别力」的诊断更精确，
但结论方向相同：单张灰度上的线索不足以支撑工程化救援。

---

## 结论与后续

**停止 DL 判别 + 框重建路线。** 与 `reports/lopdepth_falsification.md`、
`reports/residue_grow_falsification.md` 并列，构成第三条独立的证伪记录。

原有结论不变且被强化：

> 鬼影与小面积浅咬真缺陷在灰度统计上高度重叠；突破需要**新判别信息**
> （局部纹理 / 方向性 / 跨帧一致性），不是新阈值、也不是在灰度统计上重排权重的分类器。

**唯一仍开放的工业方向**（不与上述冲突）：跨帧一致性 / 多光照成像 —— 即**主动引入
新的物理信息**，而非在单张灰度上继续榨取。这也与「不上 DL」的约束不冲突。

若将来允许 DL，唯一值得做的位置仍是 **REVIEW 分流器**（把低置信结果转人工，
不承担判 NG 的责任），而非检测/分型主链路。

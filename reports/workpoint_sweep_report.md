## 裁决：证伪，不升配方

1. **最优点 d30_m18 增益在噪声内**：严格 F1 +0.02pp、严格 mAP11 +0.03pp、忽略 F1 +0.05pp、忽略 TP +8（8/6873 = 0.12%）。mAP11 排序质量**逐位持平**（90.59 vs 90.59）。以 +8 TP 换 +10 Pred，精度被稀释。不足以支撑配方升级与随之而来的 Gate/hash/四集回归成本。
2. **沿 minBlobArea 单调**：22→26 使严格 F1 −0.18pp、零重叠 GT 110→130，说明当前 22 已偏保守一侧但再收紧只是丢召回；沿 22→18 仅 +0.02pp，到底。
3. **沿 diffThreshold 单调且已过峰**：34→30→27→26 严格 mAP11 为 87.28 → 87.28 → 87.19 → 87.16。下调虽把零重叠 GT 从 110 压到 101（真的多检出 9 个），但新增框几乎全是 FP（Pred +26），净 mAP11 反降。**降阈值买到的是噪声框，不是缺陷**。
4. **d26/d27 的关键反证**：零重叠 GT 数确实下降（110→102/101），证明「弱缺陷被阈值吞掉」这一假设**方向正确但幅度不够**——要救回这 110 个零重叠 GT，阈值需下探到远低于 26 的量级，而 mAP11 在 26 已经开始塌。**不存在一个阈值区间能同时增加真召回且不增加 FP**。

## 机理证据：为什么工作点救不了零重叠漏检

对train1000 基线 `miss_dump.tsv`（110 个零重叠漏检 GT）做定位分析：

- 漏检 GT 到**同图最近候选框中心**的距离：p25=79px、中位 **107px**、p75=137px；仅 16个 <60px。
- 即这些缺陷位置**根本没有产生任何连通域候选**，不是「候选产生了但被剪枝/被 NMS 吞掉」。既然无候选，下调 minBlobArea 天然无效——这与实测 minBlobArea 22→26→单调下降、22→18 到底的现象完全一致。
- 漏检类型高度集中：**mousebite 85/110（77%）**，spur 13、short 7、open 4、pinhole 1。mousebite 属「铜被咬掉一口、剩余残影与原铜对比极弱」，在 8灰度量化 + 配准残差下根本达不到 30 灰度差阈值。
- 漏检 GT 面积中位 837px（不小），进一步排除「面积太小被面积门限杀掉」的解释。

结论：零重叠漏检的根因是**缺陷与模板的灰度对比在量化/配准噪声之下不可分**，属检测主线的信噪比问题，不是工作点标定问题。

## 对三杠杆封顶结论的影响

本次实验补齐了「检出杠杆」的最后一条低概率路径。既有封顶证据汇总：

| 杠杆 | 候选 | 裁决 |
|---|---|---|
| 检出 | C1 FWHM 逐框足迹 (footprintTau) | 证伪（τ∈[0.15,0.6] 逐位相同） |
| 检出 | D1 局部 z 通道 (seedZ) | 证伪（z 上限结构性不可达，洪水档全 FP） |
| 检出 | E1 梯度补偿亚像素 | 证伪（补偿量与弱缺陷信号同阶，F −3.2pp） |
| 检出 | 下调 diffThreshold / minBlobArea | **证伪（本文，6 组实跑，最优 +0.03pp 噪声内）** |
| 检出 | 49 零重叠真漏检 + 84 近失框 | 机理已定位为信噪比/定位精度，非末端标定 |
| 排序 | BIN 分箱置信度 + 排序神谕 | 证伪（神谕上限 90.9%，检出召回 96.8% 使 r=1.0 不可达） |
| 排序 | 边际特征 m_min / 20 特征全量池 | 证伪 |
| 分型 | SplitT / SplitC 变体 | 证伪（精度崩塌至 73% / 逐位相同） |
| 分型 | v1.2.1 SplitB(1.5×线宽窗) | **已采纳**（train1000 分型错误 209→175，官方严格 F 93.6→94.4） |
| 几何 | GrowBoxScale 扫参 / GrowBoxElong | 1.5 已定峰；各向异性伸长证伪 |

近失框补充分析（`iou_near_dump.tsv`，101 条IoU 0.2–0.33）：中心偏移中位仅 2.5px（很小），真正问题是**尺度失配**——Area/GArea 中位 0.70 但p75=3.05、双峰分布（过小 p10=0.31 与 过大 p90=3.39 并存）；47/101 卡在 0.30–0.33 窄带。单一全局缩放因子无法同时服务双峰，这解释了为何全局 1.5 定峰后各向异性改动只会掉 F。

## 后续唯一有量级的方向

在「不上 DL」约束下，已无标定类优化空间。要继续压缩差距只有两条结构性路径，均需用户开闸：

1. **提升信噪比**（而非降阈值）：更高位深/更低配准残差的输入，或配准子像素级精化——直接作用于 mousebite 这 77% 的弱对比漏检。
2. **改范式**：DL 路线（项目现有约束明确排除）。

反超官方 98.2 F / 98.6 mAP 在当前约束下不可达；v1.2.1 维持为可交付最好版本，配方与 hash 不变。
